New tool `aggregate_entries`: count, sum, average, min or max of a field over the entries `list_entries` would list, optionally grouped (a date by day, week or month) and broken down. The platform does the arithmetic (`POST /api/mcp/aggregate`), so "how much did we spend in September" no longer means paging through `list_entries` and adding up in the model. Its query parameters (`module`, `listing`, `state`, `search`, `filters`) are `list_entries`' own — one shared definition — and the platform builds one query for both, so the entries a total covers are the entries the list shows, with the same access and the same refusals. The answer says whether every matching entry was counted (`complete`) and whether groups were cut (`groupsTruncated`); an external data source such as an AutoCount book adds up in its own database and is always complete. Against a platform build without the route the tool answers `not_supported` and tells the agent to fall back to `list_entries`. The design is FETIAS `docs/analytics-aggregate-entries-proposal.md`.
